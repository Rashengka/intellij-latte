Tag and n:attribute reference
=============================

Version-stamped, one item per row. Generated by reading the registration code and
diffing it across tags; see `README.md` for the exact commands.

Sources: `src/Latte/Macros/CoreMacros.php` and `src/Latte/Macros/BlockMacros.php`
at `v2.11.7`; `src/Latte/Essential/CoreExtension.php`,
`src/Latte/Sandbox/SandboxExtension.php`,
`src/Latte/Essential/TranslatorExtension.php` and
`src/Latte/Essential/RawPhpExtension.php` at every `v3.*` tag.


Column meanings
---------------

- **2.11** / **3.0** / **3.1** — `yes`, `no`, or a version from which it exists
  within that line.
- **Form** — `{tag}` only, `n:attr` only, or `both`. In Latte 3 `both` means the
  tag's parser is a generator, which is what makes the `n:` form legal
  (`TemplateParser::addTags()`). `n:inner-` and `n:tag-` prefixes are available
  wherever `Form` is `both`.
- **Paired** — whether `{/tag}` is expected.
- **Provider** — which package must be installed for the tag to exist.
- **Deprecated** — the version from which the engine emits `E_USER_DEPRECATED`.

Attributes
----------

Every row here rejects the `n:inner-` and `n:tag-` prefixes. The first six have
no `{tag}` form at all: in Latte 2 the restriction is enforced inside the macro,
in Latte 3 the tag is registered under an `n:`-prefixed name. `n:syntax` is the
exception and is listed only so the prefix column has somewhere to say "no" —
`{syntax}` is an ordinary tag and is in the table above.

| Attribute | 2.11 | 3.0 | 3.1 | `{tag}` form | `n:inner-` / `n:tag-` | Provider | Notes |
|---|---|---|---|---|---|---|---|
| `n:attr` | yes | yes | yes | no | no | latte | 3.1 validates attribute names |
| `n:class` | yes | yes | yes | no | no | latte | 3.1 accepts arrays |
| `n:else` | no | 3.0.12 | yes | no | no | latte | paired with the previous element's `n:if` |
| `n:elseif` | no | no | 3.1.0 | no | no | latte | |
| `n:ifcontent` | yes | yes | yes | no | no | latte | 2.11 deprecates it on an empty element; 3.x errors |
| `n:tag` | yes | yes | yes | no | no | latte | not allowed inside `<script>` or `<style>` |
| `n:syntax` | yes | yes | yes | **yes**, as `{syntax}` | no | latte | `n:inner-syntax` is rejected by name in `CoreExtension::parseSyntax()` |

The `no` in the prefix column is not an inference from the registration shape —
Latte 3 strips `inner-`/`tag-` before looking the parser up, so the prefixed
form reaches the same parser and would work unless something stopped it. It was
checked by compiling `<div n:inner-class="'a'">x</div>`, `n:tag-class`,
`n:inner-attr`, `n:inner-ifcontent` and `n:inner-syntax` against v3.0.26 and
v3.1.6: all five are compile errors, while `n:inner-if`, `n:tag-if` and
`n:inner-foreach` compile.

Tags from other packages
------------------------

Read out of the bridge classes the same way as the core table, from clones of
`nette/application`, `nette/forms`, `nette/caching` and `nette/assets` (see
`README.md` for the clone commands). Latest tags surveyed: application v3.3.0,
forms v3.3.0, caching v3.4.2, assets v1.0.7, on 2026-09-04.

The version numbers in the two "since / until" columns are **package** versions,
not Latte versions — for every row except `{snippet}` / `{snippetArea}`
availability is governed by the other package, and the Latte line only decides
*which* registration class in that package is used:

| Latte line | application | forms | caching |
|---|---|---|---|
| 2.11 | `Bridges/ApplicationLatte/UIMacros::install()` | `Bridges/FormsLatte/FormMacros::install()` | `Bridges/CacheLatte/CacheMacro` |
| 3.x | `Bridges/ApplicationLatte/UIExtension::getTags()` | `Bridges/FormsLatte/FormsExtension::getTags()` | `Bridges/CacheLatte/CacheExtension::getTags()` |

`nette/assets` has no Latte 2 bridge at all; it is a Latte 3 package
(`suggest: latte/latte`, dev-required at `^3.0.22`).

| Tag | Provider | Latte 2 form | Latte 3 form | Note |
|---|---|---|---|---|
| `{cache}` | nette/caching | yes | yes | paired in both; caching conflicts with `latte/latte <3.0.12` |
| `{control}` | nette/application | yes | yes | |
| `{link}`, `{plink}` | nette/application | yes | yes | |
| `{linkBase}` | nette/application | no | **application 3.2.7+** | absent from 3.2.6 and older |
| `{ifCurrent}` | nette/application | yes | yes, **until application 3.2.12** | removed in application 3.3.0; already marked deprecated in `UIMacros.php:39` |
| `{templatePrint}` | nette/application | yes | yes | overrides the core tag of the same name |

Two constraints worth carrying into detection: `nette/application` 3.3.0 and
`nette/forms` 3.3.0 both declare `conflict: latte/latte <3.1.4 || >=3.2`, so a
project on those bridges is on Latte 3.1.4-3.1.x. `nette/caching` declares
`conflict: latte/latte <3.0.12`.

Still unverified in this table: nothing. What remains outside it is every tag a
project registers itself through `Engine::addExtension()`, which no static survey
can enumerate — the reason an "unknown tag" error is never safe.
